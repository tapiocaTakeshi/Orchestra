# 改善設計書：Electron アプリケーションのモダン・ミニマル化

本ドキュメントは、Electron ベースのアプリケーションを「Minimal (シンプルで余白を活かしたデザイン)」へと刷新するための設計方針をまとめたものである。

## 前提条件
本設計は以下の前提に基づき策定している。
- 既存のアプリは、デザインシステムが欠如しており、UI要素が過密かつ一貫性に欠けている。
- Electron の特性（メインプロセス/レンダラープロセス）を維持しつつ、フロントエンドをモダンなスタックに移行する。

---

## 1. デザイン方針 (Minimalism)
視覚的なノイズを排除し、ユーザーのタスク遂行能力を最大化する。

*   **設計指針:**
    *   **Whitespace (余白):** マージンとパディングを意図的に大きく取り、情報ブロック間の階層を明確にする。
    *   **Typography:** サンセリフ体（Inter, Noto Sans）を採用。階層構造（Heading, Body, Small）に絞り、ウェイトは Regular/Medium を主軸とする。
    *   **Color Palette:** 背景色はホワイトまたは非常に薄いグレー。テキストはチャコールグレーを使用し、純粋なブラックを避けて目に優しくする。アクセントカラーは単一に絞る。
    *   **Iconography:** ストロークが細いアイコンを採用し、視覚的な重みを軽減する。

## 2. コンポーネント設計方針 (System & Consistency)
再利用性を高め、メンテナンスコストを最小化する。

*   **指針:**
    *   **Atomic Design 準拠:** Atoms（ボタン、入力）→ Molecules（検索フォーム）→ Organisms（サイドバー、メインパネル）の構造で管理する。
    *   **Tailwind CSS の活用:** ユーティリティクラスを用いてスタイリングを迅速に行い、ビルド時に不要なスタイルを除去してバンドルサイズを最適化する。
    *   **Electron 固有の考慮:**
        *   ドラッグ領域（`-webkit-app-region: drag`）を適切に制御し、UI上のインタラクティブ要素と明確に分離する。
        *   ネイティブメニューとの共存を考慮したレイアウトにする。

## 3. 実装設計方針 (Electron Stack)
フロントエンドとバックエンドの関心事を分離し、保守性を高める。

*   **技術スタック:**
    *   **Frontend:** React + Tailwind CSS + Vite (高速ビルド)
    *   **State Management:** Zustand (軽量で Electron との相性が良好)
    *   **IPC Communication:** `electron-trpc` (メインプロセス・レンダラープロセス間を型安全に接続)
*   **ディレクトリ構成案:**
    ```text
    /src
      /main       # Main Process (Node.js)
      /preload    # Preload Scripts
      /renderer   # Frontend (React/UI)
        /components # Atomic Components
        /hooks      # Custom Hooks
        /store      # State Management
    ```

## クリティカルパスとリスク

*   **クリティカルパス:**
    *   M1（基盤） -> M2（コアレイアウト） -> M4（機能UI移行）
    *   基盤構築が遅延すると、以降のすべての UI 開発に影響するため最優先とする。
*   **主なリスク:**
    *   **互換性:** 既存機能と新 UI スタック（React/Vite）の接続時に想定外の不具合が発生する可能性がある。
    *   **コンパイル:** Electron 環境における Tailwind CSS のビルドパフォーマンス。
*   **対策:** M1のフェーズで最小構成のプロトタイプを作成し、技術的な不確実性を早期に解消する。
