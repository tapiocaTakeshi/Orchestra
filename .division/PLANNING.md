# 実装設計: Minimalデザインへの刷新

本設計は、現在のNext.js/Tailwind CSS環境を活かし、余白と視覚的階層を重視した「Minimal」デザインへ改善するための具体的なロードマップです。

## 前提
*   **技術スタック**: Next.js (App Router想定), Tailwind CSS
*   **デザイン方針**: ホワイトスペースの最大化、フォントサイズの最適化（余白と行間による視覚的余裕）、カラーパレットの限定（モノトーン＋アクセント1色）。

---

## 1. デザインガイドライン定義
*   **目的**: デザインの一貫性を担保する。
*   **Owner**: フロントエンドエンジニア
*   **Input**: 現状のUIコンポーネント
*   **Output**: `tailwind.config.js` の設定値（spacing, colors, typography）
*   **Estimated Duration**: 1時間

## 2. Global Layoutのリファクタリング
*   **目的**: 全体的な余白とマージンの標準化。
*   **Owner**: フロントエンドエンジニア
*   **Input**: `layout.tsx` または `components/layout/`
*   **Output**: Container/Wrapperコンポーネントの修正。`max-w-screen-md` または `max-w-screen-lg` を基本とし、コンテンツの幅を制限して余白を確保する。
*   **Estimated Duration**: 2時間

## 3. コンポーネント分割と刷新
*   **目的**: 冗長な装飾を取り除き、Minimalなデザインへ統一。
*   **Owner**: フロントエンドエンジニア
*   **Input**: 既存の UI コンポーネント群
*   **Output**:
    *   `atoms/Typography`: フォントサイズと行間（line-height）を厳格化。
    *   `atoms/Card`: 枠線や過度なシャドウを廃止し、背景色（gray-50）またはボーダーのみで区分け。
    *   `atoms/Button`: 角丸の調整とホバーエフェクトの簡素化。
*   **Estimated Duration**: 4時間

## 4. ページ別UIの修正
*   **目的**: 個別ページの余白とコンテンツ構造の最適化。
*   **Owner**: フロントエンドエンジニア
*   **Input**: `app/` 配下の各ページファイル
*   **Output**: 各セクション間の `gap` を均一化（例: `py-16`, `gap-y-12` 等の適用）。装飾的なグラデーションや複雑なボーダーの削除。
*   **Estimated Duration**: 3時間

## 代替案とトレードオフ

1.  **CSS Modules 併用案**
    *   メリット: Tailwindのクラスが長くなるのを防げる。
    *   デメリット: 開発環境の管理コストが増加する。
    *   判断: 今回はTailwindの管理しやすさを優先し採用しない。

2.  **UIライブラリ（Shadcn/UIなど）の導入**
    *   メリット: 高品質なMinimalコンポーネントを即座に利用可能。
    *   デメリット: 既存コードへの修正が大規模になる可能性がある。
    *   判断: 既存構成を活かすため、基本はTailwindクラスの修正にとどめる。

---

## クリティカルパスとリスク

*   **クリティカルパス**: 「1. デザインガイドライン」→「2. Global Layout」→「3. コンポーネント刷新」。ここが崩れるとデザインの不整合が全体に波及する。
*   **リスク**:
    *   **既存機能への影響**: コンポーネントを差し替える際、インタラクティブな挙動（Stateなど）が破損する可能性がある。
    *   **対策**: `testing` ツールを用いたUI回帰テストを実施し、修正前後のスクリーンショット比較を行う。
