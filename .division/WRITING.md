# SidebarChat デザイン変更ドキュメント

## 概要
`SidebarChat.tsx` のチャット UI 全体に対して、従来のフラットな見た目から、**カード感・階層感・状態の見やすさ**を強める方向でデザイン調整が入っています。  
特に以下を重視した変更です。

- 入力エリアを「操作パネル」として視認しやすくする
- アシスタント応答を「読み物」として見やすくする
- ツール実行やレビュー状態を「ステータス付きカード」で把握しやすくする
- 編集・承認・停止などの重要操作を迷いにくくする

---

## 主な変更点

## 1. 入力エリア (`VoidChatArea`)
### 変更内容
- 全体を `rounded-md` + `border` + `bg-void-bg-1` のカード風コンテナに統一
- `focus-within` / `hover` 時のボーダー変化を追加
- 下部操作列を `bg-black/80 p-1 rounded-md` で独立したフッター風に変更
- ドラッグ&ドロップ中に、青系のオーバーレイと点線ボーダーを表示
- 添付ボタンを軽量なアイコンボタン化

### 意図
- 入力欄・添付・モデル選択・送信操作をひとまとまりの「Composer」として認識しやすくするため
- DnD の操作可能性を視覚的に強く示すため
- フッター領域を分離し、入力本文と設定操作が混ざって見えないようにするため

### 影響
- 視線誘導が改善され、送信前の操作ミスが減る見込み
- 一方で `bg-black/80` はテーマ差分によってやや強く見える可能性あり

---

## 2. ユーザーメッセージ
### 変更内容
- 表示モード時のユーザーバブルを、単なる背景色ではなく
  - グラデーション背景
  - フォーカスカラーを混ぜたボーダー
  - 軽いシャドウ
  でカード化
- 右上の編集/閉じるアイコンを、枠付きのフローティングボタンとして表示

### 意図
- 「自分の発話」を独立したオブジェクトとして認識しやすくするため
- 編集可能であることを視覚的に伝えるため
- 会話ログの中で user / assistant の役割差を明確にするため

### 影響
- 以前より “発話単位” が明確
- ただし会話密度が高い場合は、カード感がやや強く感じられる可能性あり

---

## 3. アシスタントメッセージ
### 変更内容
- アシスタント応答全体を
  - `var(--void-bg-2)` ベースのグラデーション背景
  - 左アクセントボーダー
  - 角丸
  - シャドウ
  付きのコンテナで表示
- モデル名ラベルを上部ヘッダーとして追加
- 本文・reasoning・Division orchestration 表示を同一カード内に整理

### 意図
- アシスタントの応答を、単なるテキストではなく「生成結果カード」として扱うため
- 使用モデルを文脈の一部として自然に可視化するため
- reasoning / 本文 / orchestration を同一階層で読めるようにするため

### 影響
- どのモデルの返答かが追いやすい
- 返答領域が目立つ分、長文時の余白感は増える

---

## 4. ツールヘッダー (`ToolHeaderWrapper`)
### 変更内容
- ツール実行結果を共通カード UI に統一
- 左側に状態を示すアクセントラインを追加
  - 通常: `focusBorder`
  - エラー: warning
  - reject: muted
- ヘッダー内の情報構造を整理
  - タイトル
  - 対象ファイル/対象情報
  - 追加情報/件数
  - エラー・キャンセルアイコン
- 展開領域をデフォルト折りたたみ寄りにし、必要時のみ展開

### 意図
- ツール結果の見た目を統一して、ログ全体の可読性を上げるため
- 成功 / エラー / reject の状態を色と構造で即座に判別できるようにするため
- 長いログを情報密度高く保ちながら扱うため

### 影響
- ログの一覧性が大きく改善
- 一方で、各カードの余白・ボーダーが多くなるため、非常に大量のツール呼び出し時は縦の長さが増える

---

## 5. Reasoning 表示
### 変更内容
- `ReasoningWrapper` を `ToolHeaderWrapper` ベースの折りたたみ UI に変更
- 推論中は自動で開いた状態
- 推論完了後は自動で閉じる
- タイトルに「思考中」または所要秒数を表示

### 意図
- reasoning を「見たいときだけ見る補助情報」として扱うため
- ストリーミング中は状況把握しやすく、完了後は本文の邪魔をしないようにするため

### 影響
- 通常利用では本文中心の閲覧体験になる
- reasoning を頻繁に確認したいユーザーには、常時展開オプションの余地あり

---

## 6. Division orchestration 表示
### 変更内容
- Task Generation / Task Execution をそれぞれ独立カード化
- 各タスクに左アクセントストリップを付与
- ヘッダーに status / duration / provider / model などを整理して表示
- 入力コンテキストの show/hide UI を追加

### 意図
- Division API のレスポンスを、生 JSON ではなく「進行フロー」として読めるようにするため
- タスク単位で責務と結果を追いやすくするため

### 影響
- orchestration 系の情報理解がしやすくなる
- レスポンスが多い場合はカードの積み重なりがやや大きく感じる可能性あり

---

## 7. Flow review UI
### 変更内容
- `flow_review` メッセージを専用のレビューカードとして強化
- ステータス別の色分け
  - pending
  - approved
  - rejected
- ステッパー表示で工程進捗を可視化
- ドキュメントプレビューを折りたたみ表示
- 承認 / やり直しボタンを明確な CTA として配置
- 完了後・却下後の状態メッセージを追加

### 意図
- 「レビュー待ちの文書」を通常メッセージと明確に区別するため
- どの工程にいるのか、何を承認するのかを一目で理解できるようにするため
- Human-in-the-loop の操作を迷わせないため

### 影響
- レビュー操作の理解性が向上
- フェーズ名が英語混在 (`Design`, `Search`, `Writing` など) のため、日本語 UI と完全統一は今後の検討余地あり

---

## 8. コマンドバー/変更ファイルサマリ (`CommandBarInChat`)
### 変更内容
- 変更ファイル一覧を、折りたたみ可能な上部パネルとして表示
- スレッド全体 / ファイル単位のステータスインジケータを整理
- Accept All / Reject All を上部操作群として集約
- 各ファイルにも承認/拒否ボタンを配置

### 意図
- エージェント編集の結果を「会話」と「変更管理」の両面から追えるようにするため
- 大域操作と局所操作を近接配置して、レビュー負荷を下げるため

### 影響
- エディット結果のレビュー導線が改善
- ファイル数が多い場合、一覧の情報密度は追加調整の余地あり

---

## 9. サイドバーヘッダー
### 変更内容
- 右上にログイン/アカウント/設定を整理
- サインイン済みの場合はアバター表示 + ドロップダウンメニュー
- サインアウト操作をメニュー化

### 意図
- チャット本体とアカウント操作を分離しつつ、常にアクセスしやすくするため
- グローバル操作をヘッダーに集約するため

### 影響
- 操作導線は改善
- `activeTab` / `onTabChange` は受け取っているが、このファイル内ヘッダーで積極利用していないため将来拡張余地あり

---

## デザイン方針まとめ

今回の変更は大きく以下の方向性です。

1. **カード化**
   - メッセージ、ツール、レビュー、入力欄をカード的に整理し、情報のまとまりを明確化

2. **状態の可視化**
   - 実行中、承認待ち、エラー、完了、却下などを色・境界線・バッジで表現

3. **折りたたみで情報密度を制御**
   - 詳細は隠しつつ、必要時だけ展開できる構造に統一

4. **会話 + 作業ログ + レビュー の共存**
   - 単純なチャット UI ではなく、オーケストレーション作業面を扱うワークスペースとして設計

---

## 良かった点
- ユーザーが「今何が起きているか」を把握しやすくなった
- ツールログやレビュー UI の読みやすさが改善
- アシスタント返答が埋もれにくくなった
- 入力欄が単なる textarea ではなく、操作拠点として視認しやすくなった

---

## 今後の調整ポイント

## 1. テーマ互換性
- `bg-black/80`
- 青系 DnD オーバーレイ
- シャドウ表現
- グラデーションの色混ぜ

これらはダーク/ライト/高コントラストテーマで再確認が必要です。

---

## 2. 情報量が多い場面での縦伸び
カード化により視認性は上がる一方、以下で高さが増えやすいです。

- ツール呼び出しが連続するケース
- Division orchestration の多段表示
- flow review の詳細プレビュー
- 変更ファイル一覧が長いケース

必要に応じて、
- 余白の圧縮
- デフォルト折りたたみ強化
- 仮想化や省略表示
を検討すると良いです。

---

## 3. 文言の統一
UI 上で以下が混在しています。

- 日本語ラベル
- 英語ラベル
- 内部由来の技術用語
- "Error", "Approve", "Cancel" などの英語ボタン文言

今後は以下のどちらかに寄せるのが望ましいです。

- 完全日本語 UI
- 開発者向けとして一部英語を残す整理された混在

---

## 4. アイコン・色の意味づけ統一
現在は概ね整理されていますが、さらに良くするなら：

- 緑 = 承認/成功
- 赤 = 却下/エラー
- 黄/橙 = 実行中/注意
- 青 = フォーカス/現在進行中

のように意味を全体で固定すると、認知負荷をさらに下げられます。

---

## 5. モバイル的な狭幅対応・サイドバー幅依存
サイドバー幅が狭い時に以下が詰まりやすい可能性があります。

- ツールヘッダー右側のメタ情報
- flow review のステッパー
- model label
- 下部操作列の複数コントロール

必要なら将来的に、
- 2段レイアウト化
- メタ情報の省略
- アイコン主体表示
などのレスポンシブ調整が有効です。

## 要約
今回のデザイン変更は、`SidebarChat` を単なる会話欄から、**会話・推論・ツール実行・レビューを統合して扱うワークスペース UI** に近づけるものです。  
特に、**カード化・状態の見える化・折りたたみ整理**が中核であり、使い勝手と理解しやすさの向上が主目的です。  
今後は、**テーマ整合性・情報密度・文言統一**を中心に磨き込むと、さらに完成度が上がります。
