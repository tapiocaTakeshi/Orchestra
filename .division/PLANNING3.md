## UI/UX改善計画書: Orchestra プロジェクト

本ドキュメントは、`/Volumes/T7/Program/Orchestra/src` 配下の Next.js/Tailwind CSS ベースのアプリケーションに対する UI/UX 改善のロードマップです。

---

### 1. 改善方針
- **一貫性の向上**: Tailwind CSS の `tailwind.config.js` を活用し、デザイントークン（カラー、スペーシング、フォントサイズ）を再定義する。
- **UXの安定化**: ローディング状態、空の状態 (Empty States)、エラーハンドリングの標準化。
- **メンテナンス性**: 共通コンポーネントを `src/components/ui` 等に分離し、Atomic Design の考え方を部分的に適用する。

---

### 2. 対象画面・スコープ
主要なユーザーフローを対象とします。
1. **ダッシュボード画面**: 全体像の視認性向上。
2. **操作・設定画面**: フォーム入力の効率化とフィードバックの強化。
3. **リスト・詳細画面**: データ表示の整理とアクセシビリティの向上。

---

### 3. 改善ゴールと優先度

| 優先度 | 項目 | 改善ゴール | 影響範囲 |
| :--- | :--- | :--- | :--- |
| **高** | デザインシステム定義 | 色・タイポグラフィの標準化による視覚的ノイズの低減 | 全画面 |
| **高** | ローディング・エラー体験 | インタラクションのフィードバックによるストレス軽減 | 非同期処理全般 |
| **中** | フォーム入力UX | 入力エラー表示の明確化とバリデーションUXの改善 | 入力画面全般 |
| **中** | コンポーネント共通化 | コードの重複排除と保守性の向上 | 共有UI部品 |
| **低** | アニメーション追加 | 遷移やホバー時の心地よいフィードバックの付与 | インタラクション |

---

### 4. 実装順序（フェーズ分け）

#### Phase 1: 基礎基盤の整備 (Infrastructure)
- `tailwind.config.js` の整理（Color Palette, Spacing 等の変数化）。
- 共通レイアウトコンポーネントの定義（Layout.tsx 等の洗練）。

#### Phase 2: コア体験の向上 (Core Experience)
- ローディングスピナーおよびスケルトンスクリーンの実装。
- `Suspense` や `Error Boundary` の導入による失敗時のUI制御。
- Empty States（データがない場合のUI）の作成。

#### Phase 3: コンポーネント洗練 (Polishing)
- ボタン、入力フォーム、モーダルの共通化（Shadcn UI 等の知見を参考に設計）。
- アクセシビリティ（キーボード操作対応、aria属性付与）のチェック。

---

### 5. 受け入れ基準 (Acceptance Criteria)
開発したタスクが完了したと見なすための定義です。

- **視覚的一貫性**: 主要なボタン、カード、入力フォームが共通のデザインルール（Tailwind Classes）に基づいていること。
- **フィードバック**: 非同期処理中はプログレスバーまたはローディングインジケータが表示され、操作完了時にはトースト通知などが表示されること。
- **エラー処理**: 予期せぬエラー発生時にクラッシュせず、ユーザーに理解可能なメッセージを表示すること。
- **モバイル対応**: 画面幅 375px〜1280px にかけて、レイアウト崩れが発生していないこと。
- **コード品質**: 新規コンポーネントが `src/components` に適切に配置され、再利用可能であること。

---

### 6. 後続エージェントへの申し送り
- 本計画に基づき、まずは **Phase 1 (デザインシステムの定義)** から着手してください。
- 既存の Tailwind CSS クラスを直接修正する際は、`globals.css` と `tailwind.config.js` の整合性に注意してください。
- 特定のUIライブラリ（Radix UIなど）を導入する場合は、既存構成との衝突がないか確認した上で進めてください。
