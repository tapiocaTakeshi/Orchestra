# デザイン方向性案出し（SidebarChat 対象）
前提：現状 `SidebarChat.tsx` は **タブ/入力/メッセージ/ツールカード/フロー/添付UI** まで“機能は揃っている”。さらに既に **グラデーション、角丸、枠線、Prose/ToolHeaderWrapper、ステッパー、ドロップオーバーレイ**等の「凝り要素」が混ざっている。  
次の段階としては、**UIの統一感（質感）**と **階層設計（カード/ベンツ/エディタ風の役割分担）**を入れるのが最短で見栄えが伸びる。

以下、目的別に複数案を提示し、比較・採用優先度も付けます。

---

## 共通で改善したい“方向性の軸”（全案に効く）
1. **Glassmorphism の統一**
   - `bg-void-bg-*` と `border-void-border-*` が多層に混ざっているので、ガラス系は  
     - 背景：`backdrop-blur(...)`  
     - 枠：`rgba(...,0.25)` + ハイライト：`linear-gradient(...)`  
     - 影：`box-shadow` を一貫化  
     - アクティブ時：枠色/微変形（1px）/シャドウ増加  
     をカード全体に横串で適用。
2. **Bento（格子）で“情報の役割”を固定**
   - メッセージ一覧：大カード（縦）
   - 入力＋添付：固定フッター（半透明）
   - CommandBar：サブカード（横）
   - ToolHeaderWrapper：小カード（折りたたみ/ステータス）
   - FlowIndicator：カードヘッダ内 or 下部の固定帯  
   → 見た目が整うだけでなく、視線誘導が強くなる。
3. **エディタ風の部品（コード表示）を“UI言語”に統一**
   - `VoidDiffEditor`, `ChatMarkdownRender`, `CodeChildren` の周辺も含めて
     - “エディタの余白感”
     - “行番号っぽさ”
     - “copy/apply の操作密度”
     を統一。
4. **動きは軽く・一貫して**
   - 現状も `transition-all duration-200` が多いので、ガラス/ベンツ化すると
     - hover：brightness/scale 0.995
     - 展開：max-height + opacity（すでに導入済み）
     - ドロップ：拡散リング/破線の枠
     に統一する。

---

## 案A：Glass + Bento（推し・最速で“プロダクト感”が出る）
### コンセプト
**全体を“ガラスの情報ボックス（カード）”として統一**しつつ、空間を Bento グリッドで割る。  
現状のカード要素（ToolHeaderWrapper / ErrorDisplay / FlowIndicator / VoidChatArea）をそのまま活かして、見た目のルールだけ確定する。

### 見た目の特徴
- 背景レイヤ：
  - グローバル：微粒子っぽい薄いグラデ
  - カード：`backdrop-blur` + `semi-transparent` + `border with highlight`
- Bentoレイアウト：
  - メッセージエリア：カードの“縦ベンツ”（各メッセージがカード）
  - 入力：下部に固定のガラスフッター（現在の `VoidChatArea` を強化）
  - CommandBar：メッセージの上端に“サイドカー”として配置（今は同じ列内だがデザイン上は別ブロックに）

### 具体的に触る箇所（このファイル内の代表）
- `VoidChatArea`：外枠 `bg-void-bg-1` を「ガラスカード」へ
- `ToolHeaderWrapper`：背景・枠・左アクセント色・展開アニメを統一
- `ChatBubble`（User/Assistant）：背景グラデと border/影のトーンを揃える
- `ScrollToBottomContainer` のスクロールボタン：透明度・枠・影をガラス系に合わせる
- `DivisionOrchestrationComponent`：Taskカード群を“同一スタイルのガラスカード”へ

### 採用優先度
- **最優先（1位）**：既存実装を大改造せずに、統一感とプロダクト感が最速で出る。

---

## 案B：エディタ風（コードUI中心に“操作する場所”感を強く）
### コンセプト
SidebarChat を **IDE のサブパネル**として再解釈。  
チャットもカードだが、“編集/差分/操作”を主役に見せる。

### 見た目の特徴
- `ToolHeaderWrapper` を “エディタのタブ/サイドパネル”っぽい見た目に
- `EditToolChildren` / `CodeChildren` 周辺を
  - フォーカスリング
  - コード枠のダーク化
  - 行ハイライト（可能なら）  
  などで濃くする。
- “ツールは操作主体”なので、ステータス（running/done/error）を **色 + 小アイコン + バッジ**で強調。

### 具体的な施策
- `ToolHeaderWrapper` の左アクセントを現在より太くし、`title` 周りを IDE タブ風（上部に細いバー）
- `ChatBubble` は控えめにして（色は暗め）、ツールカードだけ目立つように階層制御
- `CommandBarInChat` を“差分一覧パネル”のUIとして寄せる（現在すでに近いが、枠/余白/選択状態の見せ方を統一）

### 採用優先度
- **2位**：見た目はかなり“凝ってる感”が出るが、全体統一のルール（階層）が必要で調整コストが上がる。

---

## 案C：Bento + “ガイド付き”フロー体験（エージェント可視化を主役に）
### コンセプト
このコードには `FlowIndicator` や `flow_review` が既に存在し、**エージェントの進行がUI上で見える**。  
ここを中心にして、チャット/ツールは“ガイドに従う”設計に寄せる。

### 見た目の特徴
- FlowIndicator を単なるラベルから **進捗カード（ステップバー）**へ格上げ
- `AssistantMessageComponent` の DivisionOrchestration も、カードの積み上げではなく **左右2列の bento**にする
  - 左：ステータス/理由
  - 右：出力（Markdown）
- tool request の Approve/Reject を “ステップに紐づく操作”として見せる

### 採用優先度
- **3位**：世界観は強いが、既存UIの情報設計（どこを主役にするか）の意思決定が必要。

---

## 案D：Glassmorphism “Overdrive”（より派手に、プロトタイプ向け）
### コンセプト
案Aの派生で、さらに **反射・グラデ・ノイズ・発光**を盛る。  
ただし、過剰にやると読みづらくなるため、色と透明度のガイドライン必須。

### 見た目の特徴
- カードに薄い発光（例：`box-shadow: 0 0 0 1px rgba(...), 0 10px 30px rgba(...)`）
- hover で軽い “拡散”や “角度付きグラデ”
- “active phase”だけより明るいガラスにする（FlowIndicator / ToolHeaderWrapper）

### 採用優先度
- **4位**：試作としては映えるが、プロダクトとしては調整が難しい。

---

## どれを選ぶべき？（おすすめ結論）
- **採用最優先：案A（Glass + Bento）**
  - 既存の「カード」「折りたたみ」「差分/コード表現」を活かしながら統一できる
  - 実装改修量が比較的少なく、見た目の伸びが大きい
- 次点：**案B（エディタ風）**
  - ツール/コードの体験を強くしたい場合に向く
- “世界観強め”：案C / 案D

---

## 次アクション（後続エージェント向け：この後どう進めるか）
1. **デザイン仕様を2〜3個のトークンに落とす**
   - 例：`--void-card-bg`, `--void-card-border`, `--void-accent`（error/ok/pending）
2. **カード共通コンポーネント化（最小範囲でOK）**
   - 今ある `ToolHeaderWrapper` / `ChatBubble` / `VoidChatArea` を“同じ見た目ルール”で揃える
3. **階層（主役/脇役）を決める**
   - 案Aなら：ツールカードは中くらい主役、チャットは本文主役
   - 案Bなら：ツール・コードだけ強く主役

---
