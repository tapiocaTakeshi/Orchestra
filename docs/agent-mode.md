# エージェントモード / クラウドエージェントモード / 上級者モード (表示モード)

Orchestra は VS Code をベースにしているが、Orchestra の主役は「AI エージェントに仕事を任せること」であって、
自分でコードを書くことではない。左端のアイコン列、下端のステータスバー、ミニマップ、パンくず、
レイアウトボタン……どれも「エージェントにやってほしいことを伝えて、結果を確認する」には要らない。

そこで Orchestra には **表示モード** がある。

| モード | 誰向け | 何が見える・どう動く |
| --- | --- | --- |
| エージェントモード (既定) | AI に任せて進めたい人 | ホーム画面 + エージェントへの指示欄。IDE 的な部品は隠す。チャットは常に「エージェント」、ファイル編集とコマンド実行は自動承認 |
| クラウドエージェントモード | クラウドで何本も並列に任せたい人 | Cursor の Agents 画面のように、クラウドエージェントの一覧・会話・変更だけをエディタ領域いっぱいに出す。右のチャット (手元のエージェント) は強制的に隠す |
| 上級者モード | エージェントと並んで自分でもコードを触る人 | 通常の VS Code と同じ IDE の表示。チャットモードや承認の設定も自分で選ぶ |

---

## 切り替え方

| 操作 | やり方 |
| --- | --- |
| 上級者モードにする | タイトルバー右の 🔧 ボタン / ホーム画面下部のリンク / コマンドパレット `Orchestra: 上級者モード (IDE 表示) に切り替える` |
| クラウドエージェントモードにする | タイトルバー右の ☁ ボタン / ホーム画面 (フォルダ選択済み) の **クラウドで並列に任せる** / コマンドパレット `Orchestra: クラウドエージェントモードに切り替える` |
| エージェントモードに戻す | タイトルバー右の 🤖 ボタン / コマンドパレット `Orchestra: エージェントモードに戻す` |
| エージェント ⇄ 上級者をトグル | `Ctrl+Alt+U` (macOS: `Cmd+Alt+U`) / チャット上部ヘッダーの 🤖 ボタン。クラウドエージェントモードからはエージェントモードに戻る |
| 設定画面から選ぶ | Settings > **一般** > 表示モード (3 枚のカード) |

タイトルバー右には、今のモード以外へのボタンだけが出る (☁ クラウドエージェントモード / 🤖 エージェントモード / 🔧 上級者モード)。
クラウドエージェントモードのあいだは、☁ が「クラウドエージェントのパネルを前面に出す」ボタンになる。

実体は VS Code 設定 `orchestra.ui.mode` (`"agent"` / `"cloud"` / `"pro"`) なので、settings.json に直接書いても構わない。
`"pro"` と `"cloud"` 以外の値 (未設定・旧名の `"simple"` を含む) はすべてエージェントモードとして扱う。

## エージェントモードで変わること

### エージェントの動き方

エージェントモードに入った瞬間 (切り替えたとき / 初回起動時) に、次の設定を入れる。

- チャットモードを **エージェント** (ファイル編集・ツール実行あり) にする。入力欄のチャットモード選択は出さない。
- ツールの自動承認で **ファイル編集** と **ターミナル** をオンにする。「許可」を押さなくてもエージェントが最後まで進む。

これらは通常の設定 (Settings > 一般 > ツール承認) なので、あとから個別に戻せる。戻した設定は、
次にエージェントモードへ切り替え直すまで上書きしない。

### エージェントの制御 (タイトルバー)

チャットを閉じたまま作業させることもあるので、タイトルバー右側から手が届くようにしている。

- ⏹ **エージェントを止める**: どれかのスレッドで LLM 生成中 / ツール実行中のあいだだけ出る。動いているものを全部止める。
- 🔔 **確認する**: エージェントがユーザーの承認 (自動承認していないツール、フローのレビュー) を待っているときだけ出る。
  そのスレッドへ切り替えてチャットを開く。チャットが隠れているときは通知も出す。

### レイアウト

- アクティビティバー (左端のアイコン列) とステータスバーを隠す。
- タイトルバー右に **ファイル一覧 / ターミナル / エージェント** の開閉ボタンを出す。
  アクティビティバーが無い代わりに、ここから同じものを開ける。
- 初回起動時だけ、エクスプローラーとパネル (ターミナル) を閉じ、エージェント (チャット) をウィンドウ幅の 4 割ほどに広げる。
  以降はユーザーがドラッグした幅を VS Code が覚える。

### エディタ

- ミニマップ・パンくず・グリフマージン・スティッキースクロールを off。
- 折り返し on、フォントを少し大きく (15px / 行間 1.6)。エージェントが開いたファイルを「読む」ための表示。
- エクスプローラーのフォルダをまとめて折りたたまない (`a/b/c` 表示は分かりにくい)。

### ホーム画面 (エディタが空のとき)

VS Code の透かし + ショートカット一覧の代わりに、「エージェントに何をさせるか」のホーム画面が出る。
エージェントにできること (ファイルの作成・編集 / コマンドの実行 / コードの調査とエラー修正 / 動作の確認と報告) を上に並べる。

- フォルダ未選択: 「フォルダを選ぶ → やってほしいことを伝える → エージェントが進めます」の 3 ステップと、
  **フォルダを開く** / **まずはエージェントに相談する** ボタン、最近使ったフォルダ。
- フォルダ選択済み: 「たとえば、こんな仕事を任せられます」の例 (押すとそのままエージェントに送信され、作業が始まる) と、
  **エージェントに指示する** / **ファイル一覧を見る** / **ターミナルを開く** ボタン。

### チャット (エージェントへの指示欄)

- 最初の画面に「エージェントに何をさせますか？」の一言と、任せられる仕事の例 3 つ。
  例の指示文は「作って」で終わらせず、動作確認・再実行・報告まで含めてあり、エージェントが最後まで自走する。
- 自動承認がオンなら「自律実行中: ファイル編集とコマンドは確認なしで進みます」のバッジを出す。
- 入力欄のプレースホルダを「例:「シンプルな TODO アプリを作って動かして」」のような言葉に。
- モデル選択・プロジェクト選択などの細かい行は、入力欄左下の **モデルなどの設定** を押すまで畳む。

### クラウドエージェント

手元ではなく **クラウド (Division のサンドボックス) でエージェントを動かし、いくつでも並列に任せる** こともできる。
タイトルバー右の ☁ ボタンか、ホーム画面 (フォルダ選択済み) の **クラウドで並列に任せる** で、次の「クラウドエージェントモード」に切り替わる。
モードを変えずにパネルだけを開くなら、チャット上部ヘッダーの ☁ ボタン / `Ctrl+Alt+A` (どのモードでも使える)。
詳しくは [クラウドエージェント](./cloud-agents.md)。

## クラウドエージェントモードで変わること

クラウドで動くエージェントだけを扱うための画面。Cursor の Agents 画面 (エージェントモード) のように、エディタ領域いっぱいに
**左: エージェントの一覧 / 中央: 会話と入力欄 / 右: 変更ファイルと差分** の 3 列を出す。画面の中身は [クラウドエージェント](./cloud-agents.md) を参照。

- IDE 的な部品を隠す既定値 (アクティビティバー・ステータスバー・ミニマップ……) はエージェントモードと同じものを使う。
- 入ったとき (切り替えたとき・起動時にこのモードだったとき): 右のチャット (補助バー)・サイドバー (ファイル一覧)・パネル (ターミナル) を閉じ、
  クラウドエージェントのパネルをエディタ領域に開く (固定タブ)。エディタを分割していれば、そのグループを最大化する。
- **チャットは強制非表示**: このモードのあいだは、ショートカット (補助バーの開閉など) や他のコマンドで右のチャットが開かれても、すぐに隠し直す。
  チャットを開くコマンド (`void.openSidebar` / `void.sidebar.open`) はこのモードでは何もしない。
- タイトルバーの「ファイル一覧 / ターミナル / エージェント」の開閉ボタン、⏹ エージェントを止める、🔔 確認する (どれも手元のチャット用) は出さない。
  代わりに ☁ (パネルを前面に出す)・🤖 (エージェントモードに戻す)・🔧 (上級者モード) が出る。
- パネルを閉じると、ホーム画面の代わりに「クラウドエージェントを開く / 新しいエージェント / エージェントモードに戻す」の画面が出る。
- ログインしていないときの **ログイン** は、チャットではなく設定画面 (ログインボタンがある) を開く。
- **出たとき** (エージェントモード / 上級者モードへ): チャットを戻し、入る前に開いていたサイドバー・パネルも戻す (ワークスペースごとに覚えている)。
  このモードが最大化したエディタグループも元に戻す。

## 仕組み (開発者向け)

実装は `src/vs/workbench/contrib/void/browser/orchestraUiMode.ts`。

見た目は **設定の既定値の上書き** (`IConfigurationRegistry.registerDefaultConfigurations`) で
実現している。ユーザーの settings.json には何も書き込まないし、ユーザーが同じキーを明示的に
設定していればそちらが勝つ。「エージェントモードのままミニマップだけ戻す」といったことも普通にできる。

- エージェントモードが既定なので、モジュール読み込み時点で既定値を登録しておく。クラウドエージェントモードも同じ既定値を使う。
- 上級者モードのユーザーは `WorkbenchPhase.BlockStartup` の contribution で既定値を外す。
  レイアウトの描画より前に走るので、起動時にちらつかない。
- モードはコンテキストキー `orchestra.uiMode` (`agent` / `cloud` / `pro`) にも流していて、タイトルバーのボタンの出し分けに使っている
  (`isAgentMode` / `isCloudMode` / `isProMode` の ContextKeyExpr)。
- 設定値の解釈 (`parseOrchestraUiMode`) は `orchestraUiModeTypes.ts` にあり、React・ウォーターマーク・`sidebarPane.ts` でも同じものを使う。

クラウドエージェントモードのレイアウトは `OrchestraCloudModeLayout` (`WorkbenchPhase.AfterRestored`) が受け持つ。
設定 `orchestra.ui.mode` の変化を見て入る / 出るを判断し、このモードのあいだだけ `IWorkbenchLayoutService.onDidChangePartVisibility` と
`IViewsService.onDidChangeViewContainerVisibility` を購読して、補助バーやチャットのビューが表示されたら直後 (マイクロタスク) に隠し直す。
入る前のサイドバー・パネルの表示状態は `orchestra.ui.cloudMode.savedLayout` (ワークスペースのストレージ) に覚えておき、出るときに戻す。

動作は Void の設定 (`IVoidSettingsService`) 側に書く。`chatMode: 'agent'` と `autoApprove: { edits, terminal }` を
モードに入った瞬間にだけ書き、以後はユーザーの変更を尊重する。

エージェントの稼働状況は `IChatThreadService.onDidChangeStreamState` を見て、コンテキストキー
`orchestra.agentRunning` (LLM 生成中 / ツール実行中) と `orchestra.agentAwaitingUser` (承認待ち) に流す。
タイトルバーの「止める」「確認する」はこれで出し分ける。
