# Obsidian 連携 — Vault のフォルダをエージェントのファンクションにする

Obsidian の Vault（Markdown ファイルが入ったフォルダ）を Orchestra に紐づけると、
Vault のフォルダ名を取り込み、そのフォルダ名を MCP のファンクションのように
エージェントへ公開します。エージェントがフォルダ名をテキストとして渡すと、
そのフォルダの中の Markdown ファイルを読み取ります。

Vault 全体の Markdown をまとめて読む **`all-md`** コンテキストも常に用意されます。

```
Obsidian Vault (ただのフォルダ)
   │  同期 (Settings > Obsidian の「同期」)
   ▼
Orchestra: フォルダ名を取り込む
   │
   ▼
エージェントに公開されるファンクション
   ├─ obsidian_read_folder(folder_name)  … フォルダ名をテキストで渡して読む
   ├─ obsidian_all_md                    … Vault 内の全 Markdown を読む (all-md)
   └─ obsidian_<フォルダ名>               … 取り込んだフォルダごとの個別ファンクション
```

Obsidian 本体を起動している必要はありません。Vault は単なるフォルダなので、
Orchestra はそのフォルダを直接読みます。

## セットアップ

### 1. Vault のフォルダを指定する

**Settings > Obsidian** を開き、Vault フォルダを指定します。

- 「フォルダを選択…」でダイアログから選ぶ
- またはパスを直接入力する（例: `/Users/you/Documents/MyVault`）

Obsidian 側では Vault のパスを「設定 > バージョン履歴」や Vault 切り替えメニューから
確認できます。フォルダに `.obsidian` が入っていれば、それが Vault のルートです。

### 2. 同期する

「同期」を押すと Vault を走査し、**Markdown ファイルを 1 つ以上含むフォルダ**の名前を
取り込みます。取り込んだフォルダは設定画面に一覧表示され、それぞれ ON/OFF できます。

同期はフォルダ名の取り込みだけを行います。**メモの中身はツールを呼ぶたびに
ディスクから読み直す**ので、Obsidian 側で編集した内容は再同期しなくても反映されます。
フォルダを新しく作った／名前を変えたときだけ、もう一度同期してください。

走査時に無視するもの:

- `.obsidian` / `.trash` / `.git` / `.svn` / `.hg` / `node_modules`
- 深さ 8 階層より深いフォルダ

## エージェントからの使い方

Agent モードのとき、次のファンクションがツール一覧に並びます。
（MCP ツールと違い、Vault の中を読むだけなので実行の承認は要りません。）

| ファンクション | 引数 | 動作 |
| --- | --- | --- |
| `obsidian_read_folder` | `folder_name` | 指定したフォルダの Markdown を読む |
| `obsidian_all_md` | なし | Vault 内のすべての Markdown を読む |
| `obsidian_<フォルダ名>` | なし | そのフォルダの Markdown を読む |

`folder_name` には次のどれを渡しても構いません。

- 取り込んだフォルダ名そのまま（`Projects`）
- Vault ルートからの相対パス（`Projects/2025`）
- 入れ子のフォルダの末尾だけ（`2025` → `Projects/2025` に解決）
- `all-md`（`all_md` / `allmd` / `*` も同じ）→ Vault 全体
- 空文字 / `.` → Vault 直下のメモ

### `all-md` コンテキスト

`obsidian_all_md` を呼ぶ、または `obsidian_read_folder` に `all-md` を渡すと、
Vault のすべての Markdown を読み込みます。フォルダを指定して読む場合と違い、
`all-md` はサブフォルダの設定に関係なく必ず Vault 全体を対象にします。

Vault が大きいとすぐに読み取り上限に達するので、どのフォルダにあるか分かっている
ときは `obsidian_read_folder` を使うほうが確実です。

### 読み取り結果の形式

```
# Obsidian vault: MyVault
Context: Projects
Scope: folder "Projects" (including subfolders)
Markdown files found: 12

===== Projects/roadmap.md =====
（ファイルの中身）

===== Projects/2025/q1.md =====
（ファイルの中身）
```

## 設定項目

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| Vault フォルダ | （空） | Obsidian が Vault として開いているフォルダ |
| サブフォルダも含める | ON | フォルダを読むとき、その下のフォルダのメモも読む |
| フォルダごとにファンクションを作る | ON | `obsidian_<フォルダ名>` を個別に公開する。OFF にするとツール一覧が短くなる |
| 1 回に読む最大ファイル数 | 50 | これを超えた分は読まない |
| 1 ファイルあたりの最大文字数 | 20,000 | 超えた分は切り詰めて、その旨を末尾に書く |
| 1 回の読み取りの最大文字数 | 200,000 | 合計がこれを超えたらそこで打ち切る |

上限に引っかかった場合は、読み取り結果の中にその旨が書かれるので、エージェントは
「全部は読めていない」ことを認識できます。

### フォルダが多い Vault の場合

有効なフォルダが 40 件を超えると、`obsidian_<フォルダ名>` の個別ファンクションは
公開されません（ツール一覧が膨れてモデルの精度が落ちるため）。設定画面に警告が出ます。

その状態でも `obsidian_read_folder` からはすべてのフォルダを名前で読めます。
個別ファンクションを使いたい場合は、要らないフォルダを OFF にして 40 件以下に
してください。

## 保存される場所

設定は他の Orchestra の設定と同じ場所（`GlobalSettings.obsidian`）に保存されます。

- Vault のパス
- 読み取りの上限とオプション
- フォルダごとの ON/OFF

Vault のパスを別のフォルダに変えると、フォルダごとの ON/OFF はリセットされます
（前の Vault のフォルダ名なので引き継いでも意味がないため）。

## うまく動かないとき

| 症状 | 対処 |
| --- | --- |
| 「The folder ... does not exist.」 | パスの打ち間違い。「フォルダを選択…」から選び直してください |
| フォルダが 1 つも出てこない | Vault 直下に Markdown が無いだけの可能性があります。`.md` を含むフォルダだけが取り込まれます |
| 新しく作ったフォルダが見えない | 「同期」を押し直してください（フォルダ一覧は同期時に取り込みます） |
| エージェントがフォルダ名を間違える | 設定画面の一覧に出ている名前がそのまま渡せる名前です。要らないフォルダを OFF にすると迷いにくくなります |
| 読み取りが途中で切れる | 上限に達しています。フォルダを絞るか、設定で上限を上げてください |
