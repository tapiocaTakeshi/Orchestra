# クラウドエージェント (クラウドで並列に任せる)

いつものエージェント (チャット) は、手元の PC の上で動く。ファイルを書き換えるのも、コマンドを実行するのも
自分のマシンなので、1 つの仕事が終わるまで次を頼みにくいし、PC を閉じれば止まる。

**クラウドエージェント** は、エージェントを Division のサーバー側のサンドボックス (Daytona) で動かす機能。
Claude Code の Web 版のように、仕事を投げたらあとはクラウドが進めてくれる。

- セッションごとに専用のサンドボックスが用意され、ワークスペースのコピーの上で作業する。手元の PC は空いたまま。
- **いくつでも並列に** 起動できる。別々の仕事を並べても、同じ仕事を N 個走らせて結果を比べてもよい。
- 進み具合 (エージェントの発言・ツールの実行・コマンドの出力) をその場で見られる。止めたり、追加の指示を送ったりもできる。
- 終わったら通知が届く。結果 (ファイルの変更) は **差分としてワークスペースに取り込み**、エディタで Accept / Reject する。

表示モード (エージェントモード / 上級者モード) のどちらでも使える。

---

## 開き方

| 操作 | やり方 |
| --- | --- |
| パネルを開く | タイトルバー右の ☁ ボタン / チャット上部ヘッダーの ☁ ボタン / `Ctrl+Alt+A` (macOS: `Cmd+Alt+A`) / コマンドパレット `Orchestra: クラウドエージェントを開く` |
| すぐに新しく頼む | ホーム画面 (エージェントモード・フォルダ選択済み) の **クラウドで並列に任せる** / コマンドパレット `Orchestra: 新しいクラウドエージェントを起動` |
| 動いているものを全部止める | パネルの一覧の **すべて停止** / コマンドパレット `Orchestra: 動いているクラウドエージェントをすべて止める` |

パネルはエディタ領域にタブとして開く (カンバンと同じ)。

## 使い方

### 1. 頼む

パネル左上の **新しいクラウドエージェント** に、やってほしいことを書いて **起動** (`Ctrl+Enter`)。

| 項目 | 意味 |
| --- | --- |
| 並列数 (1〜10) | 同じ指示で、独立したセッションをいくつ同時に起動するか。2 以上にするとタイトルに `#1` `#2` … が付く |
| ワークスペースを送る (既定: オン) | 開いているフォルダ (先頭のフォルダ) のファイルをサンドボックスへアップロードする。オフ、またはフォルダ未選択なら空のフォルダから始める |
| 詳細 > タイトル | 一覧に出す名前。空なら指示から自動で付く |
| 詳細 > モデル | `provider/model` 形式 (例: `anthropic/claude-opus-4-6`)。空ならプロジェクトの Coder の割り当てを使う |

### 2. 見守る

左の一覧に、セッションごとの状態が出る。

| 表示 | 状態 |
| --- | --- |
| 準備中 | サンドボックスを作っている |
| アップロード中 | ワークスペースを送っている |
| 実行中 | エージェントが作業している |
| 待機中 | 1 ターン終わった。結果を取り込むか、追加の指示を送れる |
| 失敗 | エラーで止まった。追加の指示を送るとやり直す |
| 停止 | 自分で止めた。追加の指示を送ると再開する |

セッションを選ぶと、右側にトランスクリプトが出る。自分の指示、エージェントの発言、ツールの実行
(行を開くと引数と出力が見える)、状態の変化、エラー、最後に作業のまとめ (完了カード) の順に並ぶ。

実行中のセッションが待機中 / 失敗になると、パネルを開いていなくても通知が出る (**結果を見る** でそのセッションへ飛ぶ)。

### 3. 追加の指示を送る

右下の入力欄から送る (`Ctrl+Enter`)。同じサンドボックスの中で、続きから作業する。

### 4. 変更を取り込む

**変更ファイル** タブに、サンドボックスの中で変わったファイルの一覧 (追加 / 変更 / 削除 / 名前変更、+行 / −行) が出る。
チェックを付けたものを **取り込む** か、ヘッダーの **変更を取り込む** で全部を取り込む。

- テキストファイルは、エディタに **承認待ちの差分** (緑 / 赤) として入る。勝手に保存はしないので、内容を確認して
  Accept / Reject する (チャットのエージェントが編集したときと同じ)。
- バイナリファイル (画像など) は差分にできないので、そのまま書き込む。
- 削除されたファイルは、確認ダイアログで OK したときだけローカルでも削除する (ゴミ箱へ)。
- **競合**: アップロードしたあとにローカルでも同じファイルを変えていた場合は ⚠ を付けて知らせる。
  取り込みはするが、差分は「今のローカル → クラウドの内容」になるので、自分の変更を消さないようよく確認すること。
- **パッチを表示** で、サンドボックスの `git diff` をそのまま見られる。

### 5. 片付ける

**アーカイブ** でサンドボックスを削除し、一覧から外す。取り込んでいない変更は消えるので注意。

## 仕組み

```
Orchestra (レンダラー)          Orchestra (main プロセス)            Division API                 Daytona
CloudAgentService  ── IPC ──▶  CloudAgentMainService  ── HTTPS ──▶  /api/cloud-sessions  ──▶  サンドボックス
  (状態・ポーリング)              (認証付き中継・アップロード)          (セッション・イベント)       (エージェントが作業)
```

1. **作成**: `POST /api/cloud-sessions` でセッションを作ると、Division がサンドボックスを用意する (状態: アップロード中)。
2. **アップロード**: main プロセスがワークスペースを tar.gz にまとめ、2 MiB ずつに切って `POST …/:id/upload` に順に送る。
   - git 管理のフォルダなら `git ls-files -co --exclude-standard` の結果 (= コミット済み + .gitignore されていない未追跡ファイル) を送る。
   - git 管理でなければフォルダを歩き、`node_modules` `.next` `dist` `build` `out` `.venv` `venv` `__pycache__` `.turbo` `.cache` `coverage` `target` は飛ばす。
   - `.git/` は常に送らない。1 ファイル 20 MB 超は送らない。合計 (圧縮前) が 300 MB を超えた分も送らない (どちらも「送っていない」件数として出る)。
   - 圧縮後 150 MB を超えるとエラーになる。並列数 N で起動しても、tar.gz を作るのは 1 回だけ。
   - git のブランチとコミットも一緒に記録する (詳細ヘッダーに表示)。
3. **開始**: `POST …/:id/start` でエージェントが動き出す (状態: 実行中)。並列数 N のときは 1〜3 を N 本同時に行う。
4. **見守る**: レンダラーがポーリングする。
   - 一覧 `GET /api/cloud-sessions`: 動いているセッションがある / パネルを開いているあいだは 4 秒ごと、それ以外は 30 秒ごと。
   - イベント `GET …/:id/events?after=<seq>`: 選んでいるセッションと実行中のセッションを 2 秒ごと、新しいものだけ取る。
5. **取り込み**: `GET …/:id/changes` で変更一覧とパッチを取り、ファイルごとに `GET …/:id/file?ref=current` (今の中身) と
   `ref=base` (アップロード時の中身) を取る。ローカルの中身が base と違えば競合として知らせる。

Division には CORS が無いので、認証付きの通信はすべて main プロセスを経由する。認証には、ログイン時に受け取る
ユーザー専用の Division API キー (`ak_…`、設定 `divisionUserApiKey`) を優先して使う。Supabase のセッション (JWT) は
更新されず数時間で切れるため、長くポーリングするこの機能には向かない。キーが無いときだけ JWT を使う。

## 料金・制限

- サーバー側でモデルを動かすので、**Orchestra Plus** と **Division のクレジット** が必要。足りないときはパネル上部にその旨が出る
  (設定の「プラン・支払い方法を管理」から追加・アップグレード)。並列数 N で起動すると、消費も約 N 倍になる。
- ログインの有効期限が切れると (401)、ポーリングを止めて「ログインし直してください」と出す。ログインし直すと再開する。
- アップロードできるのはローカルのフォルダだけ。リモート (SSH / WSL など) のフォルダを開いているときは、空のフォルダから始める。
  マルチルートのワークスペースでは先頭のフォルダだけを送り、先頭のフォルダへ取り込む。
- 3 MB を超えるファイルは取り込めない (サーバーの制限)。変更一覧のパッチは約 1.5 MB で切られる。
- シンボリックリンクは送らない。
- サンドボックスの中で実行したコマンドの結果 (ビルド成果物など) は、変更として出てくる分しか持ち帰れない。
- セッションの状態はサーバー側にあるので、Orchestra を閉じてもエージェントは動き続ける。次に開いたときに一覧へ戻ってくる。
