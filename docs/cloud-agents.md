# クラウドエージェント (クラウドで並列に任せる)

いつものエージェント (チャット) は、手元の PC の上で動く。ファイルを書き換えるのも、コマンドを実行するのも
自分のマシンなので、1 つの仕事が終わるまで次を頼みにくいし、PC を閉じれば止まる。

**クラウドエージェント** は、エージェントを Division のサーバー側のサンドボックス (Daytona) で動かす機能。
Claude Code の Web 版のように、仕事を投げたらあとはクラウドが進めてくれる。

- セッションごとに専用のサンドボックスが用意され、ワークスペースのコピー (または GitHub のリポジトリ) の上で作業する。手元の PC は空いたまま。
- **いくつでも並列に** 起動できる。別々の仕事を並べても、同じ仕事を N 個走らせて結果を比べてもよい。
- 進み具合 (エージェントの発言・ツールの実行・コマンドの出力) をその場で見られる。止めたり、追加の指示を送ったりもできる。
- 終わったら通知が届く。結果 (ファイルの変更) は **差分としてワークスペースに取り込み**、エディタで Accept / Reject する。

専用の表示モード **クラウドエージェントモード** があり、そこでは右のチャットを隠して、クラウドエージェントの画面だけを
エディタ領域いっぱいに出す (Cursor の Agents 画面のような形)。パネル自体はエージェントモード・上級者モードでも開ける。

---

## 開き方

| 操作 | やり方 |
| --- | --- |
| クラウドエージェントモードにする | タイトルバー右の ☁ ボタン / コマンドパレット `Orchestra: クラウドエージェントモードに切り替える` / Settings > 一般 > 表示モード |
| すぐに新しく頼む | ホーム画面 (エージェントモード・フォルダ選択済み) の **クラウドで並列に任せる** (クラウドエージェントモードに切り替えて「新しいエージェント」を開く) / コマンドパレット `Orchestra: 新しいクラウドエージェントを起動` / パネルの中で `Ctrl+N` (macOS: `Cmd+N`) |
| モードを変えずにパネルだけ開く | チャット上部ヘッダーの ☁ ボタン / `Ctrl+Alt+A` (macOS: `Cmd+Alt+A`) / コマンドパレット `Orchestra: クラウドエージェントを開く` |
| 元に戻す | タイトルバー右の 🤖 (エージェントモード) / 🔧 (上級者モード)。チャットと、入る前に開いていたファイル一覧・ターミナルが戻る |
| 動いているものを全部止める | 一覧の下の **すべて停止** / コマンドパレット `Orchestra: 動いているクラウドエージェントをすべて止める` |

パネルはエディタ領域にタブとして開く (カンバンと同じ)。

### クラウドエージェントモード

- 右のチャット (手元のエージェント)・ファイル一覧・ターミナルを閉じ、パネルをエディタ領域に開く。
- **チャットは強制非表示**。ショートカットや他のコマンドで開かれても、このモードのあいだはすぐに隠れる。
- タイトルバーには ☁ (パネルを前面に出す)・🤖 (エージェントモードに戻す)・🔧 (上級者モード) だけが出る。
- パネルのタブを閉じると、「クラウドエージェントを開く / 新しいエージェント / エージェントモードに戻す」の画面になる。

詳しくは [表示モード](./agent-mode.md)。

## 画面

Cursor の Agents 画面のような 3 列。

```
┌ 左 (エージェント一覧) ─┬ 中央 (会話) ───────────────────────┬ 右 (変更) ─────────┐
│ ＋ 新しいエージェント  │ タイトル [実行中]  モデル · 場所  ▣ │ 変更 3  +42 −7      │
│ 🔍 検索               │                                      │ [すべて取り込む]    │
│ ▾ 実行中 2             │ ┌ 指示 ───────────────────┐        │ M app.ts  +30 −2    │
│   ⟳ ログイン画面…      │ └─────────────────────┘        │ A test.ts +12       │
│ ▾ 完了 5               │ 📄 3 ファイルを読み込みました      │ ─────────────────  │
│   ● テストを直す       │ ✏️ 編集 app.ts                      │ @@ -1,4 +1,6 @@     │
│ ▾ 停止・失敗 1         │ ⌘ npm test                          │ + 追加した行        │
│                        │ ✓ 作業完了 [変更をレビュー]         │ − 消した行          │
│ user@… [すべて停止]    │ ╭ 追加の指示を送る…        ■ ↑ ╮   │                     │
└────────────────────────┴──────────────────────────────────────┴─────────────────────┘
```

- **左 (約 260px)**: **＋ 新しいエージェント** (`Ctrl+N`)・検索欄・エージェントの一覧。一覧は **実行中** (準備中 / アップロード中 / 実行中。くるくる)・
  **完了** (待機中)・**停止・失敗** に分かれる。各行はタイトル、作業している場所 (フォルダ名 / owner/name@branch)、更新時刻、
  変更の量 (読み込み済みなら `+N −M`、まだなら「N ファイル」)。行にマウスを乗せると止める / アーカイブのボタン。
  下にログイン中のアカウントと、動いているものがあれば **すべて停止**。
- **中央**: 選んだエージェントとの会話。ヘッダーにタイトル・状態・モデル・作業している場所と、止める / アーカイブ / 右パネルの開閉。
  自分の指示は枠付きの吹き出し、エージェントの発言はマークダウン、ツールの実行は 1 行ずつ (📄 読み込み・✏️ 編集・⌘ コマンド・🔍 検索・📁 一覧。
  押すと出力が開く)。続けて行った読み込み・一覧・検索は「3 ファイルを読み込みました」のように 1 行にまとまる。最後に完了カード
  (まとめ・変更ファイル数・**変更をレビュー**)。実行中は一番下へ自動でスクロールする (上にスクロールして読んでいるあいだは止まり、**最新へ** で戻れる)。
  下に入力欄が固定されていて、追加の指示を送れる (`Enter` で送信、`Shift+Enter` で改行)。実行中は ■ で止められる。
- **右 (約 360px)**: 変更ファイルの一覧 (状態 A / M / D / R と +行 / −行) と、選んだファイルの差分 (行番号付き、追加は緑・削除は赤)。
  **すべて取り込む** と、ファイルごとの **取り込む**。中央ヘッダーのボタンで開閉でき、エージェントが変更付きで作業を終えると自動で開く。
- 幅が狭いとき (約 1000px 未満) は右パネルを最初は閉じ、開くと上に重なる。さらに狭いとき (約 700px 未満) は左の一覧も畳み、中央ヘッダーのボタンで出す。

## 使い方

### 1. 頼む

左上の **＋ 新しいエージェント** を押すと、中央が「クラウドのエージェントに何を任せますか？」の画面になる (例のチップを押すと入力欄に入る)。
下の入力欄にやってほしいことを書いて `Enter` (または ↑ ボタン) で起動する。入力欄の下の行のチップで次を選べる。

| チップ | 意味 |
| --- | --- |
| 作業する場所 (📁 フォルダ名など) | 何を置いて始めるか (下の表)。フォルダを開いていれば **開いているフォルダを送る** が既定。押すと選択肢と、GitHub のリポジトリ / URL の入力が出る |
| 並列数 (×1〜×10) | 同じ指示で、独立したセッションをいくつ同時に起動するか。2 以上にするとタイトルに `#1` `#2` … が付き、起動後は 1 本目が開く |
| モデル | `provider/model` 形式 (例: `anthropic/claude-opus-4-6`)。空ならプロジェクトの Coder の割り当てを使う。同じところでタイトル (一覧に出す名前。空なら指示から自動) も付けられる |

**作業する場所** の選び方:

| 選択肢 | 意味 |
| --- | --- |
| 開いているフォルダを送る | 開いているフォルダ (先頭のフォルダ) のファイルをサンドボックスへアップロードする。フォルダ未選択なら空のフォルダから始める |
| GitHub のリポジトリ | 連携した GitHub アカウントのリポジトリとブランチを一覧から選ぶ。アップロードせず、サーバーが clone する (非公開も可)。下の「GitHub 連携」を参照 |
| URL を指定 | 公開リポジトリの `https://` URL (と任意のブランチ) を入れる。サーバーが clone する。ユーザー名やトークンを含む URL は使えない |
| 空のフォルダ | 何も置かずに始める |

### 2. 見守る

左の一覧に、セッションごとの状態が出る (実行中 / 完了 / 停止・失敗 の 3 つに分けて並ぶ)。

| 表示 | 状態 |
| --- | --- |
| 準備中 | サンドボックスを作っている |
| アップロード中 | ワークスペースを送っている |
| 実行中 | エージェントが作業している |
| 待機中 | 1 ターン終わった。結果を取り込むか、追加の指示を送れる |
| 失敗 | エラーで止まった。追加の指示を送るとやり直す |
| 停止 | 自分で止めた。追加の指示を送ると再開する |

セッションを選ぶと、中央に会話が出る。自分の指示、エージェントの発言、ツールの実行
(行を開くと出力が見える。コマンドはターミナル風に、その他のツールは引数も)、状態の変化、エラー、最後に作業のまとめ (完了カード) の順に並ぶ。

実行中のセッションが待機中 / 失敗になると、パネルを開いていなくても通知が出る (**結果を見る** でそのセッションへ飛ぶ)。

### 3. 追加の指示を送る

中央下の入力欄から送る (`Enter`。改行は `Shift+Enter`)。同じサンドボックスの中で、続きから作業する。止まっている / 失敗したセッションも、送ると再開する。

### 4. 変更を取り込む

右の **変更** パネル (中央ヘッダーのボタンで開閉、作業が変更付きで終わると自動で開く) に、サンドボックスの中で変わったファイルの一覧
(A 追加 / M 変更 / D 削除 / R 名前変更、+行 / −行) が出る。ファイルを選ぶと下に差分が出る。
**すべて取り込む** で全部を、行にマウスを乗せたときの **取り込む** (または差分の上の **取り込む**) でそのファイルだけを取り込む。

- テキストファイルは、エディタに **承認待ちの差分** (緑 / 赤) として入る。勝手に保存はしないので、内容を確認して
  Accept / Reject する (チャットのエージェントが編集したときと同じ)。
- バイナリファイル (画像など) は差分にできないので、そのまま書き込む。
- 削除されたファイルは、確認ダイアログで OK したときだけローカルでも削除する (ゴミ箱へ)。
- **競合**: アップロードしたあとにローカルでも同じファイルを変えていた場合は ⚠ を付けて知らせる。
  取り込みはするが、差分は「今のローカル → クラウドの内容」になるので、自分の変更を消さないようよく確認すること。
- 差分はサンドボックスの `git diff` をファイルごとに分けたもの。パッチが大きくて途中で切られているときや、
  変更ファイルが多くて一覧の一部しか返ってこないときは、その旨がパネルの上に出る。

### 5. 片付ける

一覧の行のアーカイブボタン、または中央ヘッダーの **アーカイブ** でサンドボックスを削除し、一覧から外す (確認あり)。取り込んでいない変更は消えるので注意。

## GitHub 連携

GitHub アカウントを連携すると、クラウドエージェントを始めるときに URL を打ったりワークスペースを送ったりせず、
自分のリポジトリ (所有・コラボレーター・所属している組織のもの) とブランチを一覧から選べる。モバイル版 (Orchestra Mobile) と同じ機能。

### 連携する

1. 入力欄の **作業する場所** のチップを押し、**GitHub のリポジトリ** を選ぶ。
2. **GitHub と連携** を押すと、システムのブラウザで GitHub の許可画面が開く。許可すると「連携しました」のページが出る。
3. Orchestra に戻ると、自動で連携が確認され「GitHub (@ユーザー名) と連携しました」と通知が出る
   (Orchestra は 2 秒ごと・最大 5 分、ウィンドウに戻ったときはすぐに状態を確かめる)。待っているあいだは **キャンセル** でやめられる。

### リポジトリを選ぶ

- 一覧は最近 push した順。検索欄に入れると (入力が止まって 300 ms 後に) サーバー側で名前を絞り込む。50 件ずつで、続きは **もっと見る**。
- 🔒 は非公開リポジトリ。選ぶとカードになり、ブランチを選べる (既定は、そのリポジトリの既定のブランチ)。**変更** で選び直す。
- 最後に選んだリポジトリとブランチは覚えておき、次回の初期値になる。
- 起動すると、一覧と会話のヘッダーに「owner/name @ branch」と出る。変更の取り込みは、いつもどおり開いているフォルダへ行う
  (取り込むなら、同じリポジトリを開いておくこと)。

### 非公開リポジトリとトークン

- GitHub のトークンは **Division のサーバーにだけ** (暗号化して) 保存される。Orchestra の PC には保存しない。
- clone もサーバーがそのトークンで行うので、非公開リポジトリも使える。トークンはそのコマンドだけに渡され、サンドボックスの `.git/config` には残らない。
- GitHub 側で許可を取り消した場合など、トークンが使えなくなると「GitHub と連携されていないか、連携が解除されています」と出て、
  未連携の表示に戻る。もう一度 **GitHub と連携** すればよい。

### 解除する

アカウント表示の **解除** を押して確認する。リポジトリを一覧から選べなくなるだけで、動いているセッションには影響しない
(URL の指定は引き続き使える)。GitHub 側の許可も消したいときは、GitHub の Settings > Applications から取り消す。

### サーバー管理者向け

GitHub 連携には、Division のサーバーに GitHub の **OAuth App** が必要。

- 環境変数 `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` を設定する。OAuth App の Authorization callback URL は `<Division API>/api/github/callback`。
- 任意で `GITHUB_TOKEN_ENCRYPTION_KEY` (32 バイトの鍵、base64 か hex)。無ければクライアントシークレットから導出する。
- 要求するスコープは `repo read:user`。
- 未設定のサーバーでは、**GitHub のリポジトリ** を選ぶと「サーバー側で GitHub 連携が未設定です」と出て、URL の指定だけになる。

## 仕組み

```
Orchestra (レンダラー)          Orchestra (main プロセス)            Division API                 Daytona
CloudAgentService  ── IPC ──▶  CloudAgentMainService  ── HTTPS ──▶  /api/cloud-sessions  ──▶  サンドボックス
  (状態・ポーリング)              (認証付き中継・アップロード)          (セッション・イベント)       (エージェントが作業)
```

1. **作成**: `POST /api/cloud-sessions` でセッションを作ると、Division がサンドボックスを用意する (状態: アップロード中)。
   GitHub のリポジトリ / URL から始めるときは、2 のアップロードを飛ばして 3 の `/start` に `repo: { fullName | url, branch? }` を付け、サーバーが clone する。
2. **アップロード**: main プロセスがワークスペースを tar.gz にまとめ、2 MiB ずつに切って `POST …/:id/upload` に順に送る。
   - git 管理のフォルダなら `git ls-files -co --exclude-standard` の結果 (= コミット済み + .gitignore されていない未追跡ファイル) を送る。
   - git 管理でなければフォルダを歩き、`node_modules` `.next` `dist` `build` `out` `.venv` `venv` `__pycache__` `.turbo` `.cache` `coverage` `target` は飛ばす。
   - `.git/` は常に送らない。1 ファイル 20 MB 超は送らない。合計 (圧縮前) が 300 MB を超えた分も送らない (どちらも「送っていない」件数として出る)。
   - 圧縮後 150 MB を超えるとエラーになる。並列数 N で起動しても、tar.gz を作るのは 1 回だけ。
   - git のブランチとコミットも一緒に記録する (詳細ヘッダーに表示)。
3. **開始**: `POST …/:id/start` でエージェントが動き出す (状態: 実行中)。並列数 N のときは 1〜3 を N 本同時に行う。
4. **見守る**: レンダラーがポーリングする。
   - 一覧 `GET /api/cloud-sessions`: 動いているセッションがある / パネルを開いているあいだは 4 秒ごと、それ以外は 30 秒ごと。
   - イベント `GET …/:id/events?after=<seq>`: 選んでいるセッションと実行中のセッションを 2 秒ごと、新しいものだけ取る。
5. **GitHub 連携**: `GET /api/github/status`・`POST /api/github/connect` (返る URL をブラウザで開く)・`POST /api/github/disconnect`・
   `GET /api/github/repos?q=&page=`・`GET /api/github/branches?repo=owner/name`。main プロセスの中継は `/api/cloud-sessions` と `/api/github`
   の下だけを通す。未連携 / トークン失効は `409 { code: 'github_not_connected' }`、OAuth App 未設定は `503 { code: 'github_not_configured' }`。
6. **取り込み**: `GET …/:id/changes` で変更一覧とパッチを取り、ファイルごとに `GET …/:id/file?ref=current` (今の中身) と
   `ref=base` (アップロード時の中身) を取る。ローカルの中身が base と違えば競合として知らせる。

Division には CORS が無いので、認証付きの通信はすべて main プロセスを経由する。認証には、ログイン時に受け取る
ユーザー専用の Division API キー (`ak_…`、設定 `divisionUserApiKey`) を優先して使う。Supabase のセッション (JWT) は
更新されず数時間で切れるため、長くポーリングするこの機能には向かない。キーが無いときだけ JWT を使う。

## 料金・制限

- サーバー側でモデルを動かすので、**Orchestra Plus** と **Division のクレジット** が必要。足りないときはパネル上部にその旨が出る
  (設定の「プラン・支払い方法を管理」から追加・アップグレード)。並列数 N で起動すると、消費も約 N 倍になる。
- ログインの有効期限が切れると (401)、ポーリングを止めて「ログインし直してください」と出す。ログインし直すと再開する。
- アップロードできるのはローカルのフォルダだけ。リモート (SSH / WSL など) のフォルダを開いているときは、空のフォルダから始める。
  マルチルートのワークスペースでは先頭のフォルダだけを送り、先頭のフォルダへ取り込む。
- 3 MB を超えるファイルは取り込めない (サーバーの制限)。変更一覧のパッチは約 1.5 MB で切られる。
- シンボリックリンクは送らない。
- サンドボックスの中で実行したコマンドの結果 (ビルド成果物など) は、変更として出てくる分しか持ち帰れない。
- セッションの状態はサーバー側にあるので、Orchestra を閉じてもエージェントは動き続ける。次に開いたときに一覧へ戻ってくる。
