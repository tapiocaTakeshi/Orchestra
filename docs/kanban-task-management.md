# カンバン (内蔵タスク管理)

Orchestra には外部サービスに依存しないカンバンボードが組み込まれている。タスクの管理も、
そのタスクをエージェントに実行させるところまで、エディタの中だけで完結する。

Trello 連携と違い、API キーもネットワークも要らない。ボードの実体はワークスペース内の
JSON ファイルなので、タスクはリポジトリと一緒に git に乗り、レビューもマージもできる。

---

## 開き方

| 操作 | やり方 |
| --- | --- |
| ボードを開閉する | `Ctrl+Alt+K` / コマンドパレット `Kanban: Toggle Board` |
| ボードを開く | `Kanban: Open Board` |
| ボードを開かずにタスクを積む | `Kanban: Add Task` |
| 実行待ちのタスクを今すぐ流す | `Kanban: Run Pending Tasks Now` |
| 自動実行を切り替える | `Kanban: Toggle Automatic Task Execution` |
| 実行中のタスクを止める | `Kanban: Cancel Running Task` |

実行に関する設定は Settings の **Kanban** タブにある。

---

## ボードの保存場所

ワークスペース直下の `.orchestra/kanban.json`。初回にボードを開いた時点で、既定のカラム構成で
作られる。

- ファイルは監視していて、外部の編集 (手編集・`git pull`・別ウィンドウ) はそのままボードに反映される。
- 逆にボード上の操作は 0.4 秒ほどまとめてからファイルに書き出される。
- JSON が壊れていた場合、既定のボードで上書きすることはしない。エラーだけ表示して、手で直す機会を残す。
- フォルダを開いていない (ワークスペースなし) 場合だけ、ファイルの代わりにアプリ内ストレージへ保存する。

チームで共有したくないなら `.gitignore` に `.orchestra/kanban.json` を足せばよい。

## カラムと「役割」

カラムは自由に追加・削除・並べ替え・改名できる。名前を日本語にしても構わない。
エージェント実行のパイプラインが見ているのは名前ではなく、カラムに設定された **役割 (role)** の方。

| 役割 | 意味 |
| --- | --- |
| 役割なし | ただの置き場。自動実行の対象にならない |
| 実行待ち (todo) | 自動実行はここからタスクを拾う |
| 実行中 (in-progress) | 実行を始めたタスクの移動先 |
| 完了 (done) | 正常終了したタスクの移動先 |
| 失敗 (error) | 失敗・タイムアウトしたタスクの移動先 |

役割は 1 つにつき 1 カラムまで。別のカラムに付け替えると、前に持っていたカラムからは自動的に外れる。
既定のボードは Backlog / To Do / In Progress / Blocked / Done の 5 本で、それぞれに上の役割が
割り当ててある。

カラム見出しの `…` から、役割・WIP 上限・色の変更と削除ができる。見出しはドラッグでカラムごと
並べ替えられる。

---

## タスク

カードには次の情報が入る。

- タイトル / 説明
- ラベル (複数)、優先度、期限、担当
- チェックリスト
- コメント (自分で書いたものと、エージェントが実行結果として書いたもの)
- 実行履歴 (状態・所要時間・エラー・最終出力・使ったチャットスレッド)
- 「自動実行の対象にするか」のフラグ

カードはドラッグでカラム間・カラム内を移動できる。クリックすると右に詳細パネルが開く。

---

## エージェント実行

カードの ▶ ボタン、または詳細パネルの「エージェントで実行」で、そのタスクをエージェントに投げる。
自動実行を on にすると、一定間隔で **実行待ち** カラムを見に行き、同じことを自動で繰り返す。

1 タスクあたりの流れ:

1. タスクを **実行中** カラムへ移す
2. タイトル・説明・チェックリスト・ラベル・優先度・期限・担当・直近のコメントからプロンプトを組み立てる
3. (設定に応じて) 新しいチャットスレッドを開き、プロンプトを流す
4. エージェントのループが終わる (かタイムアウトする) まで待つ
5. 結果をコメントとして書き戻し、実行履歴に残して、**完了** か **失敗** のカラムへ移す

エージェントは 1 スレッドにつき 1 本のループしか回せないので、実行は必ず 1 件ずつ直列に行われる。

移動先のカラム (実行中 / 完了 / 失敗) を用意していないボードでは、実行が終わってもタスクが
実行待ちカラムに残る。この場合でも自動実行が同じタスクを延々と回し続けないよう、一度拾った
タスクは記録して次のポーリングから外す。そのタスクを編集するか別の場所へドラッグすると記録は
消えるので、直してもう一度流すのは普通にできる。

### 無人実行とツール承認

無人で流している間、ツール実行の承認ダイアログを押す人はいない。承認待ちで止まると最終的に
タイムアウトするので、Settings > Feature Options の Auto-approve を有効にしておく。
承認が必要な種類が残っている状態で自動実行を on にすると、Kanban タブがその旨を警告する。
実行中に承認待ちへ入った場合は、ボード上部のバーからチャットへ飛べる。

### 設定 (Settings > Kanban)

| 設定 | 既定 | 説明 |
| --- | --- | --- |
| タスクを自動で実行する | off | 実行待ちカラムのポーリングを始める |
| ポーリング間隔 (秒) | 60 | 下限 15 秒 |
| 1 回に処理する最大タスク数 | 1 | 1 回のポーリングで流す件数の上限 |
| 1 タスクのタイムアウト (分) | 30 | 超えたら中断して失敗扱い |
| タスクごとに新しいスレッドを開く | on | off にすると 1 本のスレッドに積み上がる |
| 実行結果をコメントとして書き戻す | on | |
| このラベルが付いたタスクだけ実行 | (空) | 空なら全タスクが対象 |
| ドライラン | off | プロンプトを組み立てて記録するだけで、送信しない |
| プロンプトのテンプレート | (空 = 組み込み) | 下記のプレースホルダが使える |

### プロンプトのプレースホルダ

`{{title}}` `{{description}}` `{{checklist}}` `{{labels}}` `{{priority}}` `{{due}}`
`{{assignee}}` `{{comments}}` `{{columnName}}` `{{boardTitle}}` `{{taskId}}`

テンプレートを空にすると組み込みの既定テンプレートに戻る。

## kanban.json の形

```jsonc
{
  "version": 1,
  "title": "Orchestra Board",
  "columns": [
    { "id": "todo", "title": "To Do", "role": "todo", "wipLimit": 0, "color": "#3b82f6" }
  ],
  "tasks": [
    {
      "id": "…",
      "columnId": "todo",
      "title": "ログイン画面のバリデーションを直す",
      "description": "…",
      "labels": ["bug"],
      "priority": "high",          // urgent | high | normal | low
      "dueDate": "2026-09-01",     // '' なら期限なし
      "assignee": "",
      "checklist": [{ "id": "…", "text": "…", "done": false }],
      "comments": [{ "id": "…", "author": "agent", "body": "…", "createdAt": 0 }],
      "agentEnabled": true,
      "createdAt": 0,
      "updatedAt": 0,
      "runs": [{ "status": "done", "startedAt": 0, "endedAt": 0, "threadId": "…", "summary": "…" }]
    }
  ],
  "updatedAt": 0
}
```

カラム内の並び順は `tasks` 配列の並び順そのもの (同じ `columnId` を持つものを抜き出した順)。
順序用のフィールドは無いので、手で編集するときは配列の位置を動かせばよい。

読み込み時にはすべて正規化される。ID の重複、存在しない `columnId`、未知の優先度、
役割の重複といった壊れ方は自動的に直されるので、マージ結果をそのまま開いてもボードは壊れない。

## Trello 連携との違い

どちらも「溜まったタスクをエージェントのプロンプトとして流す」ところは同じ。

| | カンバン (内蔵) | Trello 連携 |
| --- | --- | --- |
| 保存先 | ワークスペースの `.orchestra/kanban.json` | Trello のサーバー |
| 必要なもの | なし | API キー / トークン / ネットワーク |
| タスクの編集 | Orchestra 内のボード | Trello 側 |
| git との相性 | タスクがコードと一緒に履歴に残る | 連動しない |
| チーム共有 | リポジトリ経由 | Trello 経由 (Orchestra 外からも見える) |

Trello 側で運用したい場合は Trello 連携が引き続き使える。両方を同時に有効にすることもできるが、
どちらも 1 件ずつ直列にエージェントを回すため、同時に実行しようとした方は「実行中です」と
見送られる。
